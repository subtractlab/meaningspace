# MeaningSpace

**言葉はすべて残す。持ち込むのは意味だけ。**

AI と毎日、一日中一緒に仕事をする人のための、手元で動く記憶の層。
会話の記録は要約して捨てない。その上に**行単位の住所**を持った意味の層を重ねるので、新しい会話は必要な数節だけを持ち込める。しかも、その節がどの行から来たかまで辿って戻れる。


---

## 困りごと

AI との新しい会話は、毎回ゼロから始まる。設計をまた説明する。先週失敗した直し方を、エージェントがまた試す。本題に入る前に、文脈の作り直しで使用量の枠が減っていく。

今よくある答えは2つで、どちらも痛い。

| やり方 | 起きること |
|---|---|
| **要約して元を捨てる** | 文脈には収まるが、元の考えの筋道が消える。理解が変わった時に戻る先が無い。 |
| **全部読み直す／ファイルを grep する** | 何も失わないが、問いのたびに大量に読む。しかも語で探すと、違うファイルに当たることが多い。 |

MeaningSpace は3つ目の道を取る。**地面は残し、意味を持ち運ぶ。**

## 仕組み

（図: 会話の記録［丸ごと残す・書き換えない］→ 結晶化 → 結晶［決まった／覆った／未決着 の節］→ 住所で記録に戻る。結晶 → 作法［閾値を超えた時だけ灯る］。ファイルとコード → プログレスマップ［目的・つながり・理由付きの変更台帳］→ 理由から会話の節へ）

1. **地面** — 会話はすべて行番号付きの記録として保存する。消さない、書き換えない。
2. **結晶** — 各会話を節に蒸留する。どの節も決着（決まった／覆った／未決着）と、元になった**記録の行の住所**を持つ。住所はモデルに思い出させるのではなく、*閉じた候補の中から選ばせる*。
3. **作法** — 作業の手順も結晶として持つ。検索が返すのは題名と降り方のクエリだけで、本文は閾値を超えた時にだけ読む。作法を増やしても、毎回のプロンプトは膨らまない。
4. **プログレスマップ** — ファイルとコードも同じ扱い。各ファイルが何のためにあるか、どこと繋がっているか、そして変更の台帳。変更ごとに理由と逆向き差分を持ち、その変更を生んだ会話の節に結ばれる。

本文・ベクトル・語の索引・住所・マップは全部 **1つの DuckDB ファイル**に入っている。だからクエリ1本で *意味 → 節 → 記録の行 → ファイル → 変更の理由* まで辿れる。

## 60日後に何が残っているか

どちらも「毎回すべてを説明し直す」手間を減らす。違いは、誰も予想していなかった問いが来た時に、まだ何が残っているか。

| | Claude Code のオートメモリー | MeaningSpace |
|---|---|---|
| 何が書かれるか | 作業中に Claude が残す価値があると判断したメモ | 全部の会話を、節ごとに結晶にしたもの |
| 「大事」をいつ決めるか | 書く時 | 引く時 |
| 元の会話の記録 | 保存期間を過ぎると消える | 丸ごと残し、書き換えない |
| 元の行に戻れるか | 記録が残っている間だけ | 戻れる。どの節も行の住所を持つ |
| 覆った決定 | 古いメモは気づいた時にまとめるか消す | 節ごとに「決まった／覆った／未決着」を持つ |
| 会話の最初に読み込むもの | 目次の先頭200行か25KBまで | 問いが引いた節だけ |

左の列の出典: [Claude Code のドキュメント（How Claude remembers your project）](https://code.claude.com/docs/en/memory)

オートメモリーは、その時に気づけたことに強い。MeaningSpace は、後から大事になったこと（長い経緯の本質、覆った決定、それが出てきた元の行）のために作ってある。

## ここにあるもの・無いもの

このリポジトリは**設計の公開記録（日付付き）**で、インストールできるパッケージではない。実装は公開していない。
似たものを作りたい、チームで使う話をしたい、という人は **subtractlab.com** から連絡を。

**関連する取り組み。** Graphiti も入力を元のまま「エピソード」として残し、事実をそこまで辿れる。MeaningSpace が違うのは上に乗せるもの。人や物の関係の網ではなく、文脈を持った結晶と振る舞いを変える作法を乗せ、住所は行単位まで持つ。
